# Skerry

**Skerry** 是一款面向本地项目的多 AI 协作工作台。它把项目、会话、AI 分区、管理者 AI 和执行会话组织在同一个桌面界面中，让 AI 能够在明确的权限范围内查看项目、修改文件、执行命令，并将执行结果返回到会话中。

> 当前版本：`0.1.0`
> 运行平台：Windows 10/11 与 macOS
> 项目状态：早期版本，适合本地开发验证

## 项目定位

Skerry 面向需要同时使用多个 AI 编程助手的开发者，提供一套本地优先的工作方式：

- 用项目树管理多个本地代码项目。
- 在每个项目下创建多个独立会话。
- 为会话配置多个 AI 分区，并分别选择模型和连接。
- 通过管理者 AI 分析需求，再将工作分派给执行会话。
- 在群聊时间线中查看任务派发、执行状态、文件改动和返回结果。
- 在工作区页签中预览会话产生或访问过的文件。
- 通过权限模式控制文件写入、命令执行和需要确认的操作。

Skerry 的工作台服务运行在本机，当前不提供远程团队协作服务。调用远程模型时，会根据当前会话和工具请求向对应供应商发送必要内容，请在使用前确认供应商的隐私政策和数据处理范围。

## 核心功能

### 本地项目与会话

- 使用系统文件夹选择器添加本地项目。
- 项目、会话和 AI 分区按层级管理。
- 支持项目置顶、重命名、归档和移除。
- 支持会话重命名、归档和新建。
- 每个会话保存独立的消息记录、任务记录和群聊时间线。
- 会话支持日本和美国时区设置，创建后保持不变。

### 管理者 AI 与执行会话

- 管理者 AI 负责理解用户请求和安排执行任务。
- 管理者可以查看可用的模型连接和执行会话。
- 任务可以按连接、模型或已有执行会话分配。
- 支持创建管理者分身，用于较长的资料整理、规划和总结工作。
- 执行会话完成后，结果会返回管理者视图，并同步到群聊时间线。
- 支持停止当前任务或停止会话中的全部任务。

### 文件与命令工具

根据当前权限模式，AI 可以使用以下类型的本地工具：

- 查看文件和目录。
- 搜索文件内容和文件名。
- 创建文件、修改文件和应用补丁。
- 执行 PowerShell 命令。
- 读取工作区文件并预览结果。
- 记录可复查的输入文件和输出文件。

高风险操作会进入确认流程。工具访问范围默认受项目工作区限制，是否允许访问工作区外路径由权限策略决定。

### 模型连接

Skerry 支持官方登录和自定义供应商连接：

- Claude
- Codex
- Gemini
- Grok
- 自定义 OpenAI 兼容接口
- 自定义 Anthropic 兼容接口
- 自定义 Responses 兼容接口

自定义连接支持：

- API 基础地址
- API 密钥
- 协议类型
- 模型列表地址
- 手动填写模型标识
- 拉取模型列表
- 发送简短请求测试连接

同一会话内，相同模型标识可以跨连接合并；不同版本的模型保持独立。供应商别名可以用于明确指定统一模型标识。

## 安全与数据存储

- 本地服务默认只监听 `127.0.0.1`。
- API 密钥和 OAuth 令牌：Windows 用 DPAPI，macOS 用钥匙串（服务名 Skerry）。测试或显式指定目录时退回文件。
- 软件配置默认在 `~/.skerry/`（可用 `AGENTS_DATA_DIR` 覆盖），其中不保存密钥原文。
- 浏览器开发版和桌面版使用独立的数据目录。
- 项目工作区默认母目录：`~/Downloads/Skerry工作区/`，可整体或单个项目改位置。
- Skerry 不会自动复制旧项目的用户数据或登录凭据。
- 远程 API 地址要求使用 HTTPS；仅本机地址允许使用 HTTP。

请勿把 `.data/`、桌面数据目录或包含密钥的本地文件提交到公开仓库。使用远程模型前，也请确认项目代码和会话内容是否允许发送给对应供应商。

## 快速开始

### 环境要求

浏览器开发版需要：

- Windows 10 或 Windows 11
- Node.js 22
- 可用的模型连接，或已完成的官方账号登录

桌面端开发构建还需要：

- Rust MSVC 工具链
- Visual Studio C++ 构建工具
- WebView2 运行环境

首次使用前请执行 `npm install` 安装构建工具依赖；依赖版本已记录在 `package-lock.json` 中。

### 启动浏览器版

```powershell
npm start
```

启动后访问：

```text
http://127.0.0.1:4317
```

也可以执行：

```powershell
.\launch-browser.ps1
```

### 启动桌面版

首次构建并启动：

```powershell
.\launch.ps1
```

已经完成构建后，可以双击：

```text
launch-desktop.vbs
```

## 常用命令

```powershell
# 启动本地服务
npm start

# 检查 Node.js 和前端脚本语法
npm run check

# 运行自动化测试
npm test

# 准备桌面端内置资源
npm run desktop:prepare

# 启动 Tauri 开发窗口
npm run desktop:dev

# 构建 Windows 桌面程序和 NSIS 安装包
npm run desktop:build
```

在当前版本中，自动化测试覆盖模型分组、连接配置、OAuth 状态校验、权限策略、项目树、会话、群聊、任务派发、文件工具和桌面资源准备等本地行为。

## Windows 发布文件

执行 `npm run desktop:build` 后，主要产物位于：

```text
src-tauri/target/release/bundle/nsis/Skerry_0.1.0_x64-setup.exe
src-tauri/target/release/bundle/dmg/Skerry_0.1.0_aarch64.dmg
```

macOS 代码签名不要写进仓库。本机有开发者证书时，用环境变量或本地覆盖配置，不要提交 Apple ID、Team ID 或 `signingIdentity`。

这是面向普通用户的 Windows x64 安装包，适合作为 GitHub Release 的主要下载文件。

免安装测试文件位于：

```text
src-tauri/target/release/skerry.exe
```

该文件需要与构建产生的运行时资源配合使用，不建议从安装包中单独提取后分发。Windows 安装包当前没有配置代码签名，首次安装时可能显示发布者未验证提示。

## 推荐使用流程

1. 添加一个本地项目。
2. 新建或打开一个会话。
3. 在设置中完成官方登录，或添加自定义模型连接。
4. 为会话选择管理者 AI。
5. 在会话群聊中描述目标、约束和验收条件。
6. 由管理者 AI 查看可用执行会话并安排任务。
7. 根据提示确认文件修改或命令执行。
8. 在群聊时间线和工作区页签中检查结果。

## 项目结构

```text
public/                 前端页面、工作区界面和供应商配置
src/                    本地 HTTP 服务、认证、模型连接和 Agent 执行逻辑
src/agent/              对话循环、工具、权限、任务派发和会话记录
src-tauri/              Tauri 2 桌面端配置与 Rust 启动壳
scripts/                本地服务启动和桌面资源准备脚本
public/icons/           供应商图标和应用图标
```

## 当前限制

- 真实供应商 API 调用需要使用者提供有效账号、密钥和模型权限；本地测试不等同于实网验收。
- 官方 OAuth 是否能在具体账号和网络环境中完成，需要在实际机器上单独验证。
- Gemini 官方登录依赖 Antigravity CLI 相关流程和配置好的 Google OAuth 环境变量。
- 桌面端需要 WebView2；开发构建需要 Rust MSVC 和 Visual Studio C++ 工具链。
- 安装包尚未配置代码签名。
- 项目当前以本机单用户工作方式为主，尚未提供远程协作、团队账号和集中式权限管理。

## 开发原则

- 先确认真实的本地项目、连接、会话和权限状态，再执行操作。
- 将模型配置、凭据保护、Agent 执行和界面展示分开处理。
- 只在用户授权范围内读取或修改本地文件。
- 对真实供应商、OAuth 和桌面环境行为明确标注已验证与待验证状态。

## 版本说明

`0.1.0` 是 Skerry 的早期桌面版本，重点提供本地项目管理、多 AI 会话、模型连接、管理者调度、Agent 工具和 Windows 安装包。后续版本将根据实际使用反馈继续完善模型适配、执行体验和发布流程。
